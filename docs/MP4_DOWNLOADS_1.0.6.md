# Встроенные загрузки MP4 — 1.0.6-test

Продолжение `fix/source-ui-parity` от `7aca0d6` (включает `bffd3fc` и исправления папки/PiP).

## Использование

1. Открыть фильм/серию, выбрать перевод и качество, затем «Скачать».
2. Выбрать папку через системный проводник или папку приложения. «Всегда сохранять в эту папку» сохраняет выбор; иначе место подтверждается перед каждой загрузкой. Сменить его можно в настройках загрузок.
3. Раздел «Загрузки» показывает очередь, скачивание, подготовку/сборку MP4, сохранение, паузу, ожидание сети, ошибку и готовность. «Приостановить», «Продолжить загрузку», «Повторить» управляют задачей.
4. «Воспроизвести» открывает готовый локальный файл во встроенном плеере. В выбранной папке лежит самостоятельный `video.mp4` в отдельной подпапке фильма/серии. Субтитры и постер сохраняются рядом, если доступны и включены.
5. Для старых завершённых HLS-загрузок предусмотрена кнопка «Сохранить как MP4». Она использует уже скачанный кэш или прежний пакет в выбранной папке.

## Реализация

Все новые HLS и прямые MP4 идут через одну встроенную очередь `LumenDownloadService`. Системный Android DownloadManager остаётся только для просмотра/удаления старых загрузок. Media3 отвечает за постоянный индекс, HTTP-кэш с продолжением, ограничения сети, foreground service и планировщик. Новый downloader считает задачу завершённой после сборки и полной записи MP4, а не после скачивания сегментов.

HLS собирается через `dev.ffmpegkit-maintained:ffmpeg-kit-min:8.1.7` из https://github.com/ffmpegkit-maintained/ffmpeg. Публикуемый AAR требует `com.arthenica:smart-exception-java:0.2.1`, не указанную в его POM; зависимость подключена явно, Java-связи проверены через `jdeps`. Нужен только remux (`-c copy`, `+faststart`), поэтому используется минимальная LGPL-сборка без внешних GPL-кодеков. Поддерживаются опубликованные этим FFmpeg ABI: **arm64-v8a и x86_64**, Android 7.0+.

`LocalHlsInput` строит локальные плейлисты выбранного качества и выбранного аудио. Ключи AES-128, init-сегменты, discontinuity и byte ranges переносятся из локального источника. Диапазон байтов сохраняется отдельным файлом, что позволяет работать с частично закэшированными ресурсами. FFmpeg разрешены только протоколы `file,crypto,data`; сетевой доступ во время сборки исключён.

Завершение подтверждается receipt после закрытия файла назначения. Незавершённый файл не получает кнопку воспроизведения. При паузе/завершении процесса остаются скачанные сегменты; незавершённая сборка начинается заново из них. Если MP4 уже собран, прерванное копирование в папку повторяется из готового временного MP4. После успешного сохранения кэш и временные файлы освобождаются. Сборка требует дополнительного свободного места под локальный вход и MP4.

Пауза останавливает только соответствующую native FFmpeg-сессию. Перед повторной попыткой downloader ждёт закрытия её файлов. Фоновая работа сопровождается уведомлением с текущим этапом. На время работы удерживается ограниченный partial wake lock; он освобождается при паузе, ошибке и завершении. При лимите dataSync Android 15 задача сохраняется на паузе для ручного продолжения. Принудительная остановка приложения системой/пользователем подчиняется ограничениям Android; очередь восстанавливается при запуске приложения. Для истёкших ссылок предусмотрен выбор видео заново. DRM и прямые трансляции отклоняются; несовместимые с контейнером MP4 кодеки дают ошибку с возможностью повтора.

## Проверки

- Старые тесты HLS-кэша/SAF продолжают проверять совместимость старых загрузок с `exportMp4=false`.
- `Mp4DownloadsTest`: локальный MP4 после очистки кэша/перезапуска, остановка и повтор сборки без сети, ошибка remux, прерванное копирование готового файла, обычный MP4 в SAF, преобразование старого пакета без сети. Native boundary заменён явным тестовым адаптером в проверках управления задачами.
- Отдельная интеграционная проверка запускает настоящий host FFmpeg над локальным входом, созданным из Media3-кэша: AES-128 TS, fMP4 с отдельным аудио и single-file fMP4 с byte ranges; ffprobe проверяет наличие видео, аудио и длительность. Она пропускается, если FFmpeg на host не установлен.
- `Mp4DownloadTest` запускает именно Android FFmpegKit из поставляемого AAR, проверяет аудио/видео через MediaExtractor и фактическое продвижение плеера по готовому MP4.

Синтетические медиа в `app/src/test/resources/mp4-fixture` созданы FFmpeg из testsrc/sine, не входят в production APK и не содержат реального контента или ключей сервиса. Файл `encrypted/key.bin` — публичный тестовый ключ `00..0f`.

## Установка тестового APK

APK подписан тестовым debug-ключом текущей среды. Его подпись отличается от опубликованного `artifacts/LumenKot-1.0.5-test.apk`; установка поверх той сборки завершится конфликтом подписи. Для обновления с сохранением данных соберите эту ветку с прежним ключом подписи. Удаление старого приложения удаляет его настройки и приватные загрузки, поэтому не используйте его как способ обновления без сохранения нужных данных.

Для дополнительного прогона короткого HLS-фрагмента в JVM задайте `LUMEN_HLS_SAMPLE_URL` при запуске `scripts/build.sh :app:testDebugUnitTest`; тест применяет настоящий загрузчик, локализатор HLS и host FFmpeg. Android-тест принимает необязательный аргумент instrumentation `sampleUrl` с адресом локального HTTP-стенда; после загрузки он вызывает `/block` на этом стенде и проверяет офлайн-воспроизведение MP4. Не используйте эти параметры для длинных фильмов в CI.

## Результат проверки этой сборки

- `:app:testDebugUnitTest`: 76 тестов, 0 ошибок/падений/пропусков. Включены настоящие HTTP, Media3-кэш, SQLite, SAF-провайдер и host FFmpeg 7.1.5 для проверки сборки медиа.
- `:app:assembleRelease`, `:app:assembleDebugAndroidTest`, `:app:lintDebug`: результаты и SHA-256 APK записаны в `docs/verification/mp4-1.0.6-summary.json`.
- Предоставленный пользователем источник: HTTP 200, VOD, 215 TS-сегментов, 1288.977 секунды, без AES/MAP/byte ranges. В тест взяты первые два сегмента (4 530 800 байт); получен MP4 длительностью 12.032989 секунды с H.264 1280×722 и AAC. Проверен и самостоятельный host remux, и настоящий путь загрузчика/локализатора приложения в JVM с host FFmpeg. Полное 21-минутное видео не скачивалось. Подписанная ссылка и фрагмент не входят в Git/APK/отчёт.
- Android instrumentation APK с настоящим FFmpegKit собран. Выполнить тест в этой среде не удалось: нет `/dev/kvm`, программный эмулятор API 35 не завершил запуск системных служб (`package` недоступен, затем ADB shell перестал отвечать). Это не засчитывается как проверка Android FFmpegKit или фактического воспроизведения на устройстве.
