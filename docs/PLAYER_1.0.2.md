# LumenKot 1.0.2-test

Эта сборка исправляет замечания к 1.0.1-test. Пользователь подтвердил, что реальное видео открывается после входа в аккаунт. Свои сетевые проверки здесь выполняем с локальными ответами API; учётные данные пользователя не использовались. Полный перенос остальных экранов по-прежнему не завершён.

## Изменения

- PiP: добавлены aspect ratio/source rect, автоматический вход на Android 12+, вход при Home на Android 8–11, проверка разрешения и понятное действие для его открытия. В manifest добавлены resizeableActivity и обработка screenLayout/smallestScreenSize. Плеер сохраняется при onStop видимого PiP и освобождается при закрытии/уничтожении Activity. При разворачивании явно восстанавливаются панель и контроллер.
- В мини-окне есть системные действия play/pause. Для сериалов также предыдущая и следующая серия, включая переход между сезонами. Недоступные направления и повторные переключения во время загрузки блокируются. Это RemoteAction с приватным получателем в приложении, без экспортированного управления плеером.
- Удержание 250 мс включает запрошенные пользователем **2×** и видимый индикатор. Отпускание, отмена касания и уход с экрана восстанавливают выбранную до удержания скорость. В Expo исходное удержание было 1.5×; значение 2× — явное новое требование пользователя.
- Двойное нажатие слева/справа и аппаратная перемотка показывают направление и суммарные секунды в течение двух секунд. Кнопки предыдущей/следующей серии показывают название соответствующего действия.
- Карточка: постер 40% ширины рядом с информацией, скругление 16 dp; ряд иконок рейтинга (после входа), трейлера, комментариев, закладки и загрузки; описание; отдельная красная кнопка «Смотреть». Ссылки сервиса/CDN сохранены. Загрузка постера использует заголовки клиента и прежний static host для относительных путей.
- Между сезонами и сериями добавлен разделитель 2 dp с отступами 8 dp по исходному PlayerVideoSelector.style.ts.

- Вертикальные свайпы: правая половина регулирует STREAM_MUSIC, левая — яркость только окна плеера. Есть индикатор процентов; системная настройка яркости не записывается. При входе в PiP яркость окна снимается, при возврате восстанавливается. Свайп отменяет удержание и не становится двойным нажатием. На устройствах с фиксированной громкостью показывается соответствующее сообщение.

## Продолжение просмотра

Из HTML сайта читается активная серия, которую исходный utils.ts определяет через `.b-simple_episode__item.active`. При отсутствии собственной сохранённой позиции используется этот выбор сайта. Собственный последний перевод/сезон/серия сохраняются по ID фильма, поэтому смена зеркала не сбрасывает выбор. Они выделены при открытии окна выбора через обе кнопки.

Под «Смотреть» появляется «Продолжить», когда есть позиция более 5 секунд. Ранее записанные Kotlin-ключи `position:film:voice:season:episode` читаются без миграции и удаления данных. Выход из плеера обновляет карточку. Позиция сохраняется каждые 15 секунд, при смене серии и закрытии. `/ajax/send_save` отправляется последовательной очередью процесса, не отменяется при уничтожении Activity; обычный ответ сайта с `success:false` обрабатывается как в исходнике, без проверки этого флага.

**Источник точного времени:** Expo использует `src/util/Player/index.ts` (локальное playerTime-хранилище), опционально Firebase Time share. Его `RezkaApi.saveWatch` отправляет `current_time: '1'` для истории сайта. Поэтому доступ к аккаунту сайта сам по себе не даёт возможности импортировать точные секунды из отдельного Expo-приложения. Данные Kotlin 1.0.1 и новый локальный прогресс сохраняются; существующий Time share остаётся отдельной настройкой. Чтение произвольной серверной позиции, для которой исходник не содержит API, не заявляется.

## Проверка

Сборки release/debug/AndroidTest, 30 JVM-тестов и Android Lint прошли. **Полный Android-прогон не прошёл. Реальное системное PiP не подтверждено.** Это тестовая сборка с прежним отладочным сертификатом; установка поверх 1.0.1 не удаляет cookies, настройки или позиции.

Первые Android-прогоны не засчитаны как успешные: ATD дал 7 успешных сценариев и 2 неудачных (видео не продвинулось до дедлайна, касание попало в окно другого UID); образ Google APIs получил startup ANR до первого теста одновременно с системными приложениями. На единственном обычном устройстве с отключёнными необязательными Google-приложениями повторно прошёл сценарий постера/кнопки продолжения/выбранной серии. Условие воспроизведения и фокуса окна затем не выполнилось; поверх приложения находился системный ANR-диалог. Прогон прерван для его устранения. Последний отдельный запуск PiP снова завершился до первого теста: exit-info reason=6 ANR, failed to complete startup. Эти ограничения не подменяются результатами JVM-симуляции PiP.

Полная сводка, SHA-256 APK и журналы: [player-1.0.2-checks.json](verification/player-1.0.2-checks.json). Снимки системного ANR не используются как визуальное подтверждение совпадения интерфейса. 30 JVM-тестов включают только симуляцию параметров/презентации PiP, а не настоящее мини-окно.
