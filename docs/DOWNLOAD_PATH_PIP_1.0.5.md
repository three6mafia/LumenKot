## Выбор места скачивания

После выбора озвучки, серии, качества и действия **«Скачать»** открывается диалог **«Место скачивания»**. Кнопка **«Выбрать папку»** запускает системный проводник Android. Можно выбрать существующую папку или создать новую средствами проводника. На Android 11+ корень Downloads и некоторые системные каталоги недоступны для выдачи такого разрешения; выберите подпапку.

Переключатель **«Всегда сохранять в эту папку»** по умолчанию выключен. При выключенном переключателе диалог появляется перед каждой загрузкой с последним выбранным путём. При включённом — следующие загрузки сразу используют этот путь. Настройка доступна также в **«Настройки → Загрузки»**, вместе с выбором папки. Отмена диалога или проводника не запускает скачивание. Выбранное видео и состояние переключателя переживают пересоздание Activity во время выбора папки.

Доступ к папке выдаётся через Storage Access Framework и сохраняется системным URI-разрешением; общий доступ ко всем файлам не запрашивается. Если разрешение отозвано или папка недоступна, требуется выбрать доступное место. Для устройств без системного проводника сохранён вариант **«Папка приложения»**. Изменение пути касается новых загрузок: старые остаются в своём месте и продолжают открываться.

Каждое видео в выбранной папке получает собственную подпапку. MP4 сохраняется обычным файлом `video.mp4`; HLS сохраняется пакетом сегментов с индексом для встроенного офлайн-плеера. Пакет HLS не является одним склеенным MP4. Рядом сохраняются включённые в настройках постер и субтитры. Раздел «Загрузки» показывает назначение, формат, состояние и прогресс; для MP4 в выбранной папке теперь доступны те же пауза/продолжение и удаление, что и для HLS.

## Устройство хранения

Media3 `SimpleCache` требует файловый путь и не умеет напрямую писать в SAF URI. Поэтому MP4/HLS сначала скачиваются через Media3 в папку приложения, по возможности на том же накопителе, затем переносятся в выбранную папку. Последние 15% индикатора отведены переносу. Во время переноса требуется дополнительное свободное место; после успешной проверки пакета временные сегменты удаляются.

Индекс публикуется после копирования всех сегментов. Отменённый перенос можно продолжить, сохранив уже скопированные файлы. Запись принадлежности защищает чужую непустую папку от перезаписи; удаление ограничено подпапкой конкретного видео. Соседние файлы в выбранной папке не удаляются. В индекс входят исходные и перенаправленные URI, диапазоны байтов и размеры. Локальный DataSource читает только сохранённые документы, поддерживает перемотку и byte ranges; сетевого fallback нет.

Ранее скачанные HLS продолжают читать прежний кэш. Режим «Папка приложения» сохраняет прежнюю загрузку MP4 через системный DownloadManager.

## Полноэкранный режим после PiP

При разворачивании восстанавливаются edge-to-edge и скрытие системных панелей, сбрасывается оставшийся верхний inset. Это повторяется после смены конфигурации и возврата фокуса, когда оконный переход завершён. Размер PlayerView занимает всё окно. Верхняя панель плеера следует видимости контроллера Media3 и скрывается по его таймеру; принудительное постоянное отображение после PiP убрано.

## Проверки

Команда: `scripts/build.sh :app:assembleRelease :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug`.

**69 JVM-тестов, 0 ошибок и пропусков; release/debug/AndroidTest и Android Lint прошли, ошибок Lint нет.** Новые проверки используют настоящий Downloader, локальный HTTP-сервер и тестовый DocumentsProvider: выбор/запоминание пути, отмена, пересоздание Activity, отозванное разрешение, MP4 и HLS byte ranges, продолжение переноса без сервера, воспроизведение данных после очистки временного кэша и повторного открытия хранилища, удаление с сохранением соседнего файла. Проверки PiP на JVM моделируют callback и измеряют геометрию PlayerView; они не заменяют системный оконный переход Android.

Android-прогон использует Android 15 / API 35 Google APIs x86_64 без KVM и тот же release APK, который находится в `artifacts`. Первая попытка оборвалась по startup ANR приложения на фоне системных ANR. После прогрева и предварительной проверки байткода каталог отобразился, но отдельный тест выбора папки завершился ошибкой `DocumentsUI must show the fixture folder`: системный проводник оставался пустым, а его запросы к провайдерам папок завершались тайм-аутами. Выдача доступа, скачивание в SAF и последующие Android-assertions этим прогоном не подтверждены. JVM-тесты с DocumentsProvider прошли. Отдельный PiP-тест сначала выявил ошибку ожидания в тесте при стартовом повороте; после исправления ожидания повтор завершился на `Video must actually play` (в условие входят воспроизведение и фокус окна). Переходы PiP и геометрия на Android этим прогоном не подтверждены. Полный набор из 14 Android-тестов не запускался.
