## Действия скачивания

Иконка скачивания открывает прежний выбор озвучки, сезона, серии и качества. Затем появляется меню **«Скачать» / «Поделиться ссылкой»**. Выбор качества сам по себе не начинает загрузку. Поделиться можно точным URL выбранного потока, включая параметры ссылки; cookies и служебные заголовки в отправляемый текст не добавляются. Отмена закрывает меню без скачивания.

MP4 продолжает скачиваться через системный DownloadManager. HLS сохраняется в хранилище приложения для воспроизведения встроенным плеером. В разделе **Загрузки** видны состояние и прогресс, доступны пауза, продолжение, повтор, открытие готового видео, ссылка и удаление. При просроченной ссылке можно выбрать видео заново.

## Реализация

Используется уже подключённый **AndroidX Media3 1.6.1**: `DefaultDownloaderFactory` создаёт `HlsDownloader`; `DownloadManager`, `DownloadService` и `DefaultDownloadIndex` управляют фоновой очередью и её состоянием. Дополнительный компонент — `media3-database` той же версии. Основа: [официальное руководство Android](https://developer.android.com/media/media3/exoplayer/downloading-media), [HlsDownloader](https://developer.android.com/reference/kotlin/androidx/media3/exoplayer/hls/offline/HlsDownloader).

- Подготовка разбирает плейлист средствами Media3. Для master playlist выбираются один вариант качества, связанная аудиодорожка по умолчанию и, согласно настройке, субтитры. I-frame/trick-play варианты исключаются. `StreamKey` сохраняются в запросе и передаются офлайн-плееру через `DownloadRequest.toMediaItem()`.
- Скачиваются плейлисты, сегменты, init-сегменты и AES-128-ключи. Обрабатываются относительные URL, параметры ссылок и byte ranges. HLS с непрозрачным URL распознаётся по HTTP Content-Type или `#EXTM3U`. Прямые трансляции без `ENDLIST` отклоняются; для защищённого DRM-контента требуется отдельная офлайн-лицензия.
- Сегменты остаются в `SimpleCache` с `NoOpCacheEvictor`. Выбранный накопитель записывается в метаданные каждой загрузки; изменение настройки не перенаправляет уже скачанные видео. Ключи кэша разделены по скачанным версиям, поэтому удаление одного качества сохраняет другое. Очередь и остановка пользователем хранятся в SQLite.
- Для запросов используются прежние User-Agent, Referer и CookieJar с разделением cookies по доменам. Доступ к Premium определяется сервисом. При HTTP 401/403 предлагается проверить вход и выбрать видео заново.
- Внешние субтитры и постер сохраняются согласно прежним настройкам. Сбой дополнительного файла не блокирует готовое видео; в списке появляется пояснение. Офлайн-плееру передаются только полностью сохранённые внешние субтитры.
- Офлайн-источник читает кэш без upstream-сети. Ошибка отсутствующего сегмента остаётся локальной ошибкой; незагруженное качество не подгружается из сети. Для локального просмотра отключены обращения к Time share и истории сайта, локальная позиция сохраняется.
- Сервис объявлен как `dataSync`, с каналом уведомлений и поддержкой паузы при лимите Android 15. На Android 13+ приложение предлагает разрешить уведомления. Очередь сохраняется после завершения процесса; открытие приложения возобновляет незавершённые задания, кроме явно приостановленных. Возможности автоматического перезапуска ограничиваются правилами Android и энергосбережением устройства.

## Проверки

Команда: `scripts/build.sh :app:assembleRelease :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug`.

**61 JVM-тест, 0 ошибок; сборки release/debug/AndroidTest и Android Lint прошли.** Проверки HLS используют настоящий HlsDownloader, локальный HTTP-сервер, SQLite и файловый кэш. Подтверждены выбор дорожек, сохранение и повторное открытие хранилища, продолжение частичной загрузки, сохранённая пауза очереди, удаление без повреждения другой версии, обработка недоступного накопителя, изоляция cookies и чтение без сетевого fallback. Сохранённые сегменты проверяются также после отключения сервера; декодирование синтетических сегментов JVM-тестами не заявляется.

**Целевой Android-тест `HlsDownloadTest` прошёл на Android 15 / API 35 AOSP ATD x86_64 (`OK (1 test)`).** Установлен именно release APK, обычный холодный запуск вернул `Status: ok`. Фоновый сервис скачал настоящий TS/VOD HLS, затем сервер был переведён в режим HTTP 503 для всех HLS-URL. Media3 продвинулся более чем на 500 мс при длительности ≥3 сек., без ошибок и без новых HLS-запросов. Полный набор из 12 Android-тестов этим прогоном не запускался.

Для повторения нужен локальный fixture из `tools/generate-hls-fixture.sh`. Первая попытка instrumentation завершилась startup ANR до начала теста; после успешного обычного запуска release APK повторный целевой прогон прошёл. Фактические журналы, результаты и SHA-256 APK находятся в [verification/hls-1.0.4-checks.json](verification/hls-1.0.4-checks.json).

Доступ к реальному Premium-аккаунту, съёмная SD-карта и длительные фоновые загрузки на физических устройствах в этой среде не проверены. Общая работа над соответствием интерфейса исходному Lumen продолжается.
