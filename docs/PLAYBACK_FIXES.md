# Проверка запуска видео и ошибки входа

Это рабочая диагностическая версия, не завершённый перенос интерфейса оригинала.

Сообщения пользователя: после «Смотреть» пусто; вход завершался `Value <!doctype ... cannot be converted to JSONObject`. Конкретный пример: https://rezka-ua.pub/series/comedy/1154-teoriya-bolshogo-vzryva-2007-latest.html.

## Подтверждённые расхождения с исходником

- POST API использовал `/ajax/get_cdn_series?t=...`, тогда как исходный postRequest добавляет `/` перед query. Теперь сохраняются POST и multipart-поля по пути `/ajax/get_cdn_series/?t=...`.
- Для `get_episodes` исходник принимает объект с `seasons`/`episodes`, не требуя `success: true`. Kotlin теперь принимает такой ответ и отклоняет явный `success: false`.
- JSON обработчик пытался разобрать HTML как JSONObject. Теперь отдельно распознаются HTML, страницы проверки браузера, перенаправление POST в GET и обычные HTTP ошибки. Текст ошибки не включает пароль, cookies, полный ответ или подписанные URL потоков.
- Видеоплеер использовал общий API клиент с лимитом 50 секунд на весь запрос, что непригодно для длинного потока. Для Media3 снят общий call timeout, а сетевые connect/read timeout сохранены.

## Интерфейс

Восстановлены основные действия и расположение из Player.component.tsx: заголовок/иконки сверху, play/pause и предыдущая/следующая серия в центре, длительность/шкала/часы снизу; двойное нажатие для перемотки и удержание 1.5x, блокировка управления, выбор перевода/серии, комментарии, закладки, отправка исходной ссылки и масштаб. Окно выбора возвращено к центрированной округлой панели с палитрой исходника, списком переводов и кнопками сезонов/серий. Выбор перевода фильма или серии запускает получение видео, как в исходнике; для единственного перевода фильм загружается сразу. Вместо пустого состояния при получении потока окно сохраняет индикатор, текст ошибки и повтор. Не перенесены storyboard preview шкалы, рейтинги переводов, индикаторы просмотренных серий, все жесты/анимации, полное TV управление и точное оформление всех дополнительных overlay-компонентов. Это не полный визуальный перенос.

## Реальная страница пользователя

Обычный curl к rezka-ua.pub дал HTTP 403. С браузерным User-Agent получен HTTP 200, но после распаковки gzip заголовок страницы — «Проверяем, что вы не бот!». В ней **нет** `b-translator__item`, `b-simple_season__item` и `initCDNSeriesEvents`. Реальный Kotlin тест этой страницы не получил карточку/потоки. К rezka.ag в этой среде по-прежнему отказ на CONNECT (403).

HTTP 200 не засчитывается как успешная загрузка сериала. Учётные данные пользователя не запрашивались и не использовались. Доступ к реальному видео без ответа сайта в этой среде не подтверждён.

## Автономные проверки

19 JVM тестов прошли, включая форму POST для видео, сезоны без success, HTML вместо JSON, POST redirect и распознавание browser challenge. assembleRelease/assembleDebug и Android Lint прошли.

Отдельный Android прогон проверяет получение видео через native API, выбор серии при единственном переводе, воспроизведение локального MP4 новым контроллером и блокировку его управления. Итог финального прогона: **OK (7 tests)**, API 35 AOSP ATD, 250.5 с. Полный вывод — [playback-android-smoke.txt](verification/playback-android-smoke.txt), сводка с SHA-256 APK — [playback-checks.json](verification/playback-checks.json). Эти данные не подменяют проверку реального сериала и визуальное сравнение с оригиналом.

## Закрытие плеера

Повторный Android-прогон выявил настоящий дефект: поздний onPlayerError после уничтожения SurfaceView пытался вызвать AlertDialog.show на закрывающемся Activity и получал WindowManager.BadTokenException. Ошибка воспроизводилась при закрытии тестового плеера. Исправление: сообщение рисуется внутри существующего экрана; callback игнорируется после остановки/закрытия; released устанавливается до отсоединения surface.

Первый запуск инструментальных тестов не выполнил сценарии: программный эмулятор получил ANR на проверке checksum DEX при старте (одновременно зависали его системные службы). После штатного `cmd package compile -m verify` без отключения проверок раннер дошёл до реального дефекта закрытия плеера. Исходные неудачные прогоны не считаются успешной проверкой.

При повторном запуске среды эмулятор несколько раз терял системный NetworkStack, и установка APK обрывалась до старта приложения. Эти попытки также не засчитаны. После восстановления служб, отдельной загрузки APK и штатной проверки пакетов финальный полный прогон прошёл без ошибок.
