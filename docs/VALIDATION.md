# Проверки и границы переноса

Исходная ревизия `three6mafia/lumen`: `ca1d93967da8d8414db1f98e44b632a16d90f507` (master). Исходный checkout не изменён.

## Подтверждено в этой среде

- `assembleDebug` и `assembleRelease` завершаются успешно.
- `testDebugUnitTest`: **11 тестов, 0 ошибок, 0 пропусков**. Проверены каталог/пагинация, сезоны и серии, inline-видео, декодирование замусоренного Base64, неизменность URL и субтитры. Дополнительно Robolectric проверяет создание Activity в светлой и тёмной теме, настоящий HTTP к MockWebServer, сохраняемые cookies/изоляцию доменов, поиск/комментарии и историю.
- `lintDebug`: **0 ошибок**. Остаются рекомендации по ресурсам/локализации, PiP, KTX и версиям библиотек; проверки не отключались, baseline не добавлялся.
- `apksigner verify`: устанавливаемый APK подписан схемой v2. Используется локальный отладочный сертификат; это не production signing key.
- Передаваемый release APK установлен в Android 15 ATD: `adb install` → `Success`, холодный запуск `MainActivity` → `Status: ok`.
- `aapt dump badging`: package `com.lumenkot.app`, min SDK 24, target SDK 35, имя `LumenKot`.
- В APK нет React Native bundle или native runtime. UI написан на Kotlin/Android Views с Jetpack Compose, видео воспроизводит Media3, HTTP/HTML обрабатывают OkHttp/Jsoup.
- Реестр исходных URL сохранён в `original-links.json`. Зеркала, CDN, статический сервер изображений, ссылки проекта и JSON обновлений оригинала не перенаправлялись на другие сервисы.

## Проверка на устройстве

В `app/src/androidTest` подготовлены интеграционные тесты для локального сервера `tools/smoke_server.py`: HTTP-каталог/фильм/потоки/поиск/комментарии, cookie persistence и разделение доменов, история, запуск Activity, продвижение позиции Media3 при воспроизведении MP4. На Android 15 / API 35 AOSP ATD x86_64 выполнены **5 тестов, 0 ошибок** (`OK (5 tests)`). Media3 действительно продвинулся по тестовому MP4; проверена позиция >500 мс и длительность ≥3 сек.

Первый прогон имел 3 сетевых сбоя, потому что ATD не имел маршрута к `10.0.2.2`. После настройки `adb reverse tcp:8765 tcp:8765` и loopback-адреса все 5 тестов прошли. Эта коррекция затрагивает только тестовый маршрут, не штатные зеркала приложения.

## Что ещё не подтверждено

- Доступность реальных зеркал/CDN и работа входа с реальным аккаунтом. Эти сервисы зависят от региона, блокировок, подписки и текущей HTML-разметки.
- Доступ к исходному Firebase-проекту из нового application ID и синхронизация с оригинальным Lumen. Сохранены проект и структура `timestamps`/`savedTime`; возможны серверные ограничения, которые нельзя проверить без включения функции с реальным аккаунтом.
- Физические Android TV, разные пульты, SD-карты, долгие загрузки, HLS/субтитры реального провайдера и восстановление после убийства процесса.
- Пиксельное совпадение UI с оригиналом: это нативный интерфейс с системными диалогами и фокусом, а не автоматическая конверсия JSX.

## Известные отличия

- Интерфейс этой версии русский; поддерживаются системная, светлая и тёмная темы. Полный набор переводов, анимаций и тонких настроек оригинала ещё не перенесён.
- Просмотр: формат HLS/MP4 подписан в существующем выборе качества. Скачивание: отдельная форма качества, формата, нескольких серий и субтитров; папку выбирает системный SAF. Новые MP4/HLS обслуживает Media3 (ProgressiveDownloader/HlsDownloader), сохранение в папку — WorkManager. Старые загрузки системного DownloadManager остаются доступны. Внутренний кеш сохраняется до удаления загрузки, поэтому требуется место и для кеша, и для файлов в выбранной папке.
- Трейлеры и внешние ссылки открываются системным приложением. Автообновление из прежнего JSON не устанавливает APK оригинального React Native Lumen поверх LumenKot: ссылка доступна в настройках как обновления оригинала.
- Комментарии отображаются компонентом Compose `CommentText`: Jsoup разбирает структуру, `AnnotatedString`/`Text` отображают жирный/курсив/подчёркивание/зачёркивание, цитаты, списки, код и ссылки. Каждый спойлер раскрывается и скрывается нажатием прямо в тексте независимо от остальных. Изображения представлены alt-текстом; внешние CSS и JavaScript не исполняются. Состояние спойлеров хранится через Compose `rememberSaveable`.
- Нативная версия не переносит существующую локальную MMKV-базу оригинального приложения; используются отдельные настройки/история/cookies. Серверные закладки доступны после входа в тот же аккаунт.

Эти отличия означают, что сборка представляет нативный перенос основных сценариев, **а не завершённое соответствие всем функциям оригинала один к одному**.

## Compose и HLS: сохранение прежнего интерфейса LumenKot

По уточнению пользователя ориентир — предыдущий LumenKot, а не React Native Lumen. Цвета, верхнее меню, подписи, карточки и навигация сохранены. Дополнительный экран выбора формата убран: формат подписан в прежнем диалоге качества. Комментарии рисует Compose; сетка использует BoxWithConstraints по доступной ширине без пересоздания страницы при изменении размеров. Экран и плеер используют Compose-контейнеры с AndroidView для существующих элементов; это совместное использование Views и Compose, не полный перенос всех экранов на Compose.

Для HLS добавлена foreground-служба типа dataSync и системный планировщик Media3. Загрузки хранят индекс и сегменты на диске, видны в прежнем разделе «Загрузки». Удаление проходит через Media3 и очищает соответствующий кеш. APK 1.0.3-test имеет versionCode 4 и подписан тем же локальным debug-ключом.

В этой среде запуск эмулятора API 35 невозможен: отсутствует KVM/поддержка аппаратной виртуализации. Поэтому проверки установки, внешнего вида на устройстве и фактического воспроизведения нового APK пока не выполнены. JVM-регрессия HLS использует настоящий HlsDownloader и HTTP-сервер: скачивает плейлист и сегмент, отключает сервер, читает оба объекта из кеша без upstream, затем проверяет удаление. Прежние отчёты о проверках на устройстве выше относятся к исходной сборке.

Для 1.0.3-test выполнены **16 JVM-тестов, 0 ошибок**. Compose-навигация проверена через стандартный `createEmptyComposeRule`: сохранение прежнего меню и реальный переход к полю поиска. Эмуляторная проверка нового APK остаётся недоступной по указанной выше причине.

Release-сборка `assembleRelease` и `lintDebug` завершились успешно, Lint — **0 ошибок** (предупреждения остаются). Подпись нового APK проверена `apksigner verify`; package/versionCode/minSdk сверены через `aapt dump badging`. APK размещён в `artifacts/LumenKot-1.0.3-test.apk`, SHA-256 — в `artifacts/SHA256SUMS`.

## 1.0.4-test: загрузки, поиск и полноэкранный режим

Ориентиры: исходный Expo/React Native `three6mafia/lumen` и текущий Kotlin `three6mafia/LumenKot`. Оформление и навигация Kotlin сохранены. Форма скачивания написана на Compose, комментарии и контейнер плеера продолжают использовать Compose/AndroidView.

- «Скачать»: выбор HLS/MP4, качества, набора серий (включая все), субтитров. Доступность выбранного качества проверяется для каждой серии; неподходящая серия вызывает явную ошибку, без молчаливой подмены качества.
- Системный OpenDocumentTree выбирает папку с сохраняемым URI-разрешением. При включённом «Запомнить место сохранения» следующая загрузка использует сохранённую папку; выключение заставляет снова открыть выбор папки. Переключатель есть в форме и настройках. Можно явно выбрать другую папку.
- HLS: стандартный HlsDownloader; при отключённых субтитрах StreamKeys исключают отдельные HLS-дорожки субтитров. MP4: стандартный ProgressiveDownloader. Индекс и загрузка сохраняются в Media3 DownloadService; экспорт в выбранную папку выполняет foreground WorkManager.
- MP4 сохраняется как `video.mp4`, HLS — как `video.m3u8` с локальными ссылками на сегменты, ключи AES и init-map. Байтовые диапазоны сохраняются отдельными ресурсами с обновлением плейлиста. Выбранные внешние субтитры сохраняются рядом. Постер скачивается по существующей настройке, его ошибка не блокирует готовое видео. HLS не конвертируется в единый MP4.
- После завершения экспорта раздел «Загрузки» открывает локальные content URI. Удаление отменяет экспорт, удаляет созданную для загрузки подпапку и кеш Media3. Подготовка запроса сохраняет данные пакета перед системным выбором папки.
- Поиск: карточки приходят автоматически после 350 мс без ввода, есть пагинация; очистка поля удаляет карточки. Устаревший ответ не применяется к новому запросу. Кнопка «Найти» и голосовой ввод сохранены.
- Добавлено зеркало `https://rezka.fi` и его host для Android deep links. Реальная доступность зеркала и CDN не подтверждалась.
- Плеер: decorFitsSystemWindows=false, видео без системного padding, cutout-отступы применяются только к панели управления. Полноэкранность повторно применяется при возвращении фокуса, resume, изменении конфигурации и серии; конкурентная смена серий отменяет прежний запрос. Закрытие PiP удаляет matching AppTask целиком; обычное сворачивание/возврат из PiP и блокировка экрана не должны закрывать задачу.

JVM-проверки: **28 тестов, 0 ошибок**. В том числе Compose-форма параметров/нескольких серий/обоих состояний переключателя папки; HLS StreamKeys без субтитров; экспорт MP4 и двух разных HLS-сегментов в тестовое дерево DocumentsContract после отключения HTTP-сервера; локальные URI, ключи/map/byterange; автоматический поиск и очистка; три сценария жизненного цикла плеера/PiP. Для дерева используется тестовый ContentProvider контракта DocumentsContract и эмуляция выданного URI-разрешения: реальный системный picker/SD-карта на устройстве не проверены.

`assembleRelease` и `lintDebug` успешны, Lint — **0 ошибок**, предупреждения остаются. Номер APK: 1.0.4-test, versionCode 5. Новая сборка визуально на устройстве и с системным PiP не проверена: в среде отсутствует KVM. Это ограничивает подтверждение исправлений отступов и PiP реальным Android; тесты проверяют код жизненного цикла, а не системное окно PiP.
