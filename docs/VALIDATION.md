## Проверка на устройстве

В `app/src/androidTest` подготовлены интеграционные тесты для локального сервера `tools/smoke_server.py`: HTTP-каталог/фильм/потоки/поиск/комментарии, cookie persistence и разделение доменов, история, запуск Activity, продвижение позиции Media3 при воспроизведении MP4. На Android 15 / API 35 AOSP ATD x86_64 выполнены **5 тестов, 0 ошибок** (`OK (5 tests)`). Media3 действительно продвинулся по тестовому MP4; проверена позиция >500 мс и длительность ≥3 сек.

Первый прогон имел 3 сетевых сбоя, потому что ATD не имел маршрута к `10.0.2.2`. После настройки `adb reverse tcp:8765 tcp:8765` и loopback-адреса все 5 тестов прошли. Эта коррекция затрагивает только тестовый маршрут, не штатные зеркала приложения.

## Что ещё не подтверждено

- Доступность реальных зеркал/CDN и работа входа с реальным аккаунтом. Эти сервисы зависят от региона, блокировок, подписки и текущей HTML-разметки.
- Доступ к исходному Firebase-проекту из нового application ID и синхронизация с оригинальным Lumen. Сохранены проект и структура `timestamps`/`savedTime`; возможны серверные ограничения, которые нельзя проверить без включения функции с реальным аккаунтом.
- Физические Android TV, разные пульты, SD-карты, долгие загрузки, HLS/субтитры реального провайдера и восстановление после убийства процесса.
- Пиксельное совпадение UI с оригиналом: это нативный интерфейс с системными диалогами и фокусом, а не автоматическая конверсия JSX.

## Известные отличия

- Интерфейс этой версии русский; поддерживаются системная, светлая и тёмная темы. Полный набор переводов, анимаций и тонких настроек оригинала ещё не перенесён.
- Существующий диалог качества показывает доступные варианты HLS/MP4 (если источник предоставляет их). Парсер сохраняет все альтернативные URL после `or`, включая подписанные query-параметры. Формат и качество можно переключить в плеере с сохранением позиции; при смене серии сохраняется формат, если он доступен. Загрузки используют системный DownloadManager и каталог приложения. «Скачать» предлагает MP4 и HLS. MP4 обслуживается системным DownloadManager; HLS — стандартным `HlsDownloader` через Media3 DownloadManager/DownloadService, с постоянным SimpleCache и DownloadIndex. HLS хранится во внутренней памяти приложения; настройка накопителя применяется к MP4. HLS воспроизводится из кеша с отключённым сетевым источником; поддерживаются удаление и повтор после ошибки. Внешние субтитры и постеры отдельно для HLS не скачиваются; дорожки в самом HLS обрабатывает стандартный загрузчик. Постеры и субтитры могут скачиваться рядом с MP4, доступны настройки внутреннего/внешнего накопителя. Работа со съёмной SD-картой не проверена.
- Трейлеры и внешние ссылки открываются системным приложением. Автообновление из прежнего JSON не устанавливает APK оригинального React Native Lumen поверх LumenKot: ссылка доступна в настройках как обновления оригинала.
- Комментарии отображаются компонентом Compose `CommentText`: Jsoup разбирает структуру, `AnnotatedString`/`Text` отображают жирный/курсив/подчёркивание/зачёркивание, цитаты, списки, код и ссылки. Каждый спойлер раскрывается и скрывается нажатием прямо в тексте независимо от остальных. Изображения представлены alt-текстом; внешние CSS и JavaScript не исполняются. Состояние спойлеров хранится через Compose `rememberSaveable`.
- Нативная версия не переносит существующую локальную MMKV-базу оригинального приложения; используются отдельные настройки/история/cookies. Серверные закладки доступны после входа в тот же аккаунт.

Эти отличия означают, что сборка представляет нативный перенос основных сценариев, **а не завершённое соответствие всем функциям оригинала один к одному**.

## Compose и HLS: сохранение прежнего интерфейса LumenKot

По уточнению пользователя ориентир — предыдущий LumenKot, а не React Native Lumen. Цвета, верхнее меню, подписи, карточки и навигация сохранены. Дополнительный экран выбора формата убран: формат подписан в прежнем диалоге качества. Комментарии рисует Compose; сетка использует BoxWithConstraints по доступной ширине без пересоздания страницы при изменении размеров. Экран и плеер используют Compose-контейнеры с AndroidView для существующих элементов; это совместное использование Views и Compose, не полный перенос всех экранов на Compose.

Для HLS добавлена foreground-служба типа dataSync и системный планировщик Media3. Загрузки хранят индекс и сегменты на диске, видны в прежнем разделе «Загрузки». Удаление проходит через Media3 и очищает соответствующий кеш. APK 1.0.3-test имеет versionCode 4 и подписан тем же локальным debug-ключом.

В этой среде запуск эмулятора API 35 невозможен: отсутствует KVM/поддержка аппаратной виртуализации. Поэтому проверки установки, внешнего вида на устройстве и фактического воспроизведения нового APK пока не выполнены. JVM-регрессия HLS использует настоящий HlsDownloader и HTTP-сервер: скачивает плейлист и сегмент, отключает сервер, читает оба объекта из кеша без upstream, затем проверяет удаление. Прежние отчёты о проверках на устройстве выше относятся к исходной сборке.

Для текущей версии выполнены **16 JVM-тестов, 0 ошибок**. Compose-навигация проверена через стандартный `createEmptyComposeRule`: сохранение прежнего меню и реальный переход к полю поиска. Эмуляторная проверка нового APK остаётся недоступной по указанной выше причине.

Release-сборка `assembleRelease` и `lintDebug` завершились успешно, Lint — **0 ошибок** (предупреждения остаются). Подпись нового APK проверена `apksigner verify`; package/versionCode/minSdk сверены через `aapt dump badging`. APK размещён в `artifacts/LumenKot-1.0.3-test.apk`, SHA-256 — в `artifacts/SHA256SUMS`.
